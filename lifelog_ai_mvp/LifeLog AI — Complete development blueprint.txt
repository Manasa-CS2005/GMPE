# LifeLog AI
## Complete Application Development Plan

**Project type:** Full-stack, multimodal Generative AI application  
**Primary purpose:** Transform voice notes, recordings, photographs and documents into personalized journals, organized memories, actionable tasks and creative content.

---

# 1. Complete Feature Scope

## Module 1: User Registration, Login and Authentication

### 1.1 Registration
- Create an account using name, email address and password.
- Validate email format and password strength.
- Check whether the email is already registered.
- Hash passwords securely before storing them.
- Verify email address.
- Accept privacy policy and terms of service.
- Display appropriate success and error messages.

### 1.2 Login
- Login using email and password.
- Secure session management.
- Remember-me option.
- Logout from the current session.
- Logout from all sessions.
- Login error handling and rate limiting.
- Forgot-password and password-reset workflow.

### 1.3 Account Security
- Email verification.
- Secure password reset using expiring tokens.
- Optional two-factor authentication as an enhancement.
- Session expiration and refresh.
- Protection against brute-force login attempts.
- Account deletion and data removal workflow.

**Completion requirement:** Users must be able to register, log in, log out, reset their password and access only their own private data.

2. **Quick actions:** Record voice note, upload files, write a journal and view tasks.
3. **Today's activity:** Notes, recordings, photographs and generated entries.

## Module 4: Daily Input and Memory Capture

Users should have several ways to capture their day.

### 4.1 In-app voice recording
- Start, pause, resume and stop recording.
- Display a recording timer.
- Display recording status and audio levels where supported.
- Preview the recording before submission.
- Play, delete or re-record before saving.
- Upload the recording for transcription.
- Display transcription progress and errors.

### 4.2 Upload audio recordings
Supported formats should include commonly used formats such as WAV, MP3, M4A and WebM, subject to the transcription provider's capabilities.

Features:
- Select one or more audio files.
- Validate file type and size.
- Display upload progress.
- Play uploaded recordings.
- Transcribe recordings into text.
- Edit the transcript before AI processing.
- Keep the original recording when the user chooses to retain it.

### 4.3 Text input
- Write daily notes manually.
- Save drafts.
- Edit previously written notes.
- Add titles, tags and dates.
- Autosave drafts.
- Continue an unfinished journal entry.

### 4.4 Photograph uploads
- Upload photographs from a device.
- Preview and remove photographs.
- Add captions and tags.
- Attach photographs to a particular day's memory.
- Extract image descriptions using a vision-capable model.
- Allow users to edit or reject extracted descriptions.

### 4.5 Document and file uploads
- Upload PDF, TXT, DOCX and other explicitly supported formats.
- Preview filenames, sizes and upload status.
- Extract readable text from supported documents.
- Attach documents to daily memories.
- Summarize documents when requested.
- Extract relevant events, plans or tasks from uploaded material.
- Preserve the original file for later access, subject to user settings.

### 4.6 Multiple-input daily memory
A user should be able to combine a voice recording, typed notes, photographs and documents into one daily memory.

For example, a user uploads a voice note describing a college presentation, a photograph from the event and a PDF containing project notes. LifeLog AI organizes these inputs under the same day and uses the available evidence to create a journal.

## Module 5: Speech-to-Text and Multimodal Understanding

### Processing pipeline

1. Receive text, audio, images or documents.
2. Validate and store the original inputs.
3. Transcribe audio into editable text.
4. Extract text from supported documents.
5. Generate descriptions for relevant images when requested.
6. Combine selected information into a unified daily record.
7. Detect duplicate or overlapping information where feasible.
8. Ask the user to correct ambiguous details.
9. Send the approved information to the day-understanding engine.

### Important rules
- Do not invent events, people, locations or achievements.
- Distinguish explicit facts from AI-generated suggestions.
- Do not assume a person's emotional state solely from a photograph.
- Preserve dates and names accurately where possible.
- Allow users to correct transcription errors.
- Make processing failures recoverable.

## Module 6: AI Day-Understanding Engine

This is the core intelligence layer of LifeLog AI.

It converts unstructured inputs into a structured representation of the user's day.

### Information to extract
- Events and activities.
- People and places explicitly mentioned.
- Important moments.
- Achievements and completed work.
- Challenges and concerns.
- Feelings explicitly described by the user.
- Pending tasks.
- Future plans.
- Deadlines and times when explicitly provided.
- Goals and intentions.
- Memories linked to photographs or documents.

### Structured output

The system should produce validated data with fields such as:

- Date and summary.
- Events.
- Achievements.
- Challenges.
- User-described mood.
- Completed tasks.
- Pending tasks.
- Future plans.
- Important moments.
- Source references.

Use Pydantic models or equivalent schema validation to ensure consistent output.

Each extracted item should retain its source where practical, allowing the user to verify why the system included it.

## Module 7: Prompt Modes and Personalized Generation

Users should choose how LifeLog AI processes and presents their memories.

### Required modes

**1. Simple Journal**
- Convert the note into a natural diary entry.
- Preserve the user's meaning.
- Avoid unnecessary details.

**2. Personal Persona**
- Generate a warm, first-person and reflective entry.
- Adapt to the user's saved writing preferences.

**3. Structured Day**
- Organize events, achievements, challenges and pending tasks into sections.

**4. Reflection Mode**
- Summarize what went well.
- Identify challenges described by the user.
- Offer gentle reflection questions.
- Suggest practical lessons without inventing experiences.

**5. Explain Through an Analogy**
- Explain a complicated event, concept or lesson using a suitable analogy.
- Let the user request a simpler or more detailed explanation.

**6. Vlog Creator**
- Convert the day's events into a short-video script.
- Include a hook, suggested shots, voice-over and ending.

**7. Social Media Creator**
- Generate captions, story text, reel scripts and hashtags.
- Provide alternative tones and lengths.
- Keep personal information private unless the user chooses to share it.

**8. Custom Prompt Mode**
- Allow users to enter their own instructions.
- Provide reusable saved prompts.
- Validate the requested output format.

### Generation controls
- Short, medium and detailed output lengths.
- First-person or third-person writing.
- Formal, casual, emotional or professional tone.
- Regenerate, edit, save, copy and export.
- Compare different prompt outputs.

- Save generated entries.

- Add dates, tags and titles.

## Module 9: Task Management and To-Do Lists

LifeLog AI should turn explicitly identified pending actions into manageable tasks.

### Task features
- Extract tasks from voice notes and documents.
- Create tasks manually.
- Edit task titles and descriptions.
- Set due dates and times.
- Assign priorities.
- Mark tasks complete or incomplete.
- Postpone or reschedule tasks.
- Delete tasks.
- Filter by pending, completed and overdue.
- Link tasks to the memory from which they originated.
- Display tasks on the dashboard and calendar.

### Task validation
The AI must not invent deadlines. If a note says, "I should contact my teammate tomorrow," the system may suggest a task for tomorrow, but it should identify the date as an interpreted suggestion and let the user confirm it.

## Module 10: Schedule Generator and Smart Reminders

### Schedule generator
- Suggest a daily plan using tasks and user-selected availability.
- Allow users to set working hours and preferred routines.
- Provide editable time blocks.
- Resolve scheduling conflicts where possible.
- Let users approve the proposed schedule before saving.

### Reminder system
- Create reminders manually.
- Create proposed reminders from extracted tasks.
- Require confirmation for uncertain deadlines.
- Support one-time and recurring reminders.
- Allow reminders to be edited, snoozed or dismissed.
- Display upcoming reminders.
- Send notifications through supported channels.

### Notification channels
- In-app notifications.
- Email reminders.
- Browser or mobile push notifications as a later enhancement.

**Technical requirement:** The AI proposes tasks and reminder times; a real scheduler and notification service deliver the reminders. Notifications must not depend on the user keeping the app open.

# 2. Recommended Technical Architecture

## Frontend
**React + TypeScript + Vite**

Responsibilities:
- Registration and login screens.
- User profile.
- Dashboard.
- Voice recording interface.
- File upload interface.
- Journal editor.
- Memory timeline.
- Task manager.
- Calendar and reminders.
- Vlog and social-media studio.
- Responsive desktop and mobile layouts.

## Backend
**Python + FastAPI**

Responsibilities:
- Authentication and authorization.
- User and profile management.
- File upload processing.
- Audio transcription.
- AI orchestration.
- Structured extraction.
- Journal and task APIs.
- Reminder scheduling.
- Search and export.
- Validation and error handling.

## Database
**PostgreSQL + SQLAlchemy + Alembic**

Store:
- Users and profiles.
- Sessions or refresh-token records.
- Memories and source references.
- Transcripts.
- Generated outputs.
- Tasks and schedules.
- Reminders and notification status.
- File metadata.
- User preferences.

SQLite can be used during local experimentation, but PostgreSQL is the recommended database for the multi-user application.

## File storage
Use a storage abstraction that can support local development storage and later S3-compatible object storage.

Store file metadata in PostgreSQL and the actual audio, image and document files in file storage.

## AI and processing services
- Speech-to-text model or service for voice recordings.
- LLM service for structured extraction and generation.
- Vision-capable model for optional image descriptions.
- Optional image-generation service.
- Pydantic for validating AI output.
- Background job processing for longer tasks.

Use configurable model providers so the application is not tied permanently to one AI vendor.

## Background jobs and reminders
Use a job queue and worker for longer transcription and generation tasks. A Redis-backed queue such as Celery is one option.

A persistent scheduler or scheduled-job service should handle reminders. Store reminder times and delivery status in the database so jobs can be retried safely.

## Deployment
- Frontend hosting.
- Backend API hosting.
- Managed PostgreSQL or a secured database server.
- Persistent object storage.
- HTTPS.
- Environment-based configuration.
- Error monitoring and backups.

# 4. Database Design

The database should be designed around these entities.

| Entity | Purpose |
|---|---|
| Users | Account credentials, identity and account status |
| UserProfiles | Personal preferences and profile information |
| Sessions | Active sessions or refresh-token metadata |
| Memories | A daily memory and its date, title and status |
| SourceAssets | Audio, photographs, documents and other uploads |
| Transcripts | Transcribed text and processing metadata |
| ExtractedEvents | Events, achievements, challenges and plans |
| GeneratedOutputs | Journal entries, reflections, captions and scripts |
| Tasks | Pending and completed actions |
| Schedules | User-approved time blocks |
| Reminders | Reminder times, status and recurrence |
| Notifications | In-app and external delivery records |
| Tags | Reusable memory labels |
| MemoryTags | Many-to-many relationship between memories and tags |
| UserPrompts | Custom and saved generation prompts |
| AIJobRecords | Processing status, errors and usage metadata |
| AuditEvents | Security-relevant events without unnecessary private content |

Every user-owned record must have an ownership relationship to the appropriate user account. All API queries must enforce that relationship.

# 5. Core Application Workflow

## Daily memory workflow

**Step 1:** User logs in.

**Step 2:** User opens the dashboard and selects Create Memory.

**Step 3:** User records a voice note, types text or uploads recordings, photographs and documents.

**Step 4:** The application validates the inputs and stores them securely.

**Step 5:** Audio is transcribed; supported documents and images are processed when requested.

**Step 6:** The user reviews and corrects the source text.

**Step 7:** The AI extracts events, achievements, challenges, tasks and plans into validated structured data.

**Step 8:** The user chooses a generation mode.

**Step 9:** The AI generates the journal, reflection, tasks, vlog script, caption and suggestions.

**Step 10:** The user reviews, edits and saves the outputs.

**Step 11:** The user confirms any proposed tasks, schedules or reminders.

**Step 12:** The dashboard and memory timeline update.

**Step 13:** The user can return later to search, edit, export or delete the memory.

# 6. API Design

The backend should expose documented, versioned REST endpoints.

Example endpoint groups:

### Authentication
- `POST /api/v1/auth/register`
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/logout`
- `POST /api/v1/auth/forgot-password`
- `POST /api/v1/auth/reset-password`
- `POST /api/v1/auth/verify-email`
- `POST /api/v1/auth/refresh`

### Profile
- `GET /api/v1/users/me`
- `PATCH /api/v1/users/me`
- `DELETE /api/v1/users/me`

### Memories and files
- `GET /api/v1/memories`
- `POST /api/v1/memories`
- `GET /api/v1/memories/{memory_id}`
- `PATCH /api/v1/memories/{memory_id}`
- `DELETE /api/v1/memories/{memory_id}`
- `POST /api/v1/assets/upload`
- `POST /api/v1/assets/{asset_id}/transcribe`

### AI processing
- `POST /api/v1/memories/{memory_id}/extract`
- `POST /api/v1/memories/{memory_id}/generate`
- `GET /api/v1/jobs/{job_id}`

### Tasks and reminders
- `GET /api/v1/tasks`
- `POST /api/v1/tasks`
- `PATCH /api/v1/tasks/{task_id}`
- `DELETE /api/v1/tasks/{task_id}`
- `GET /api/v1/reminders`
- `POST /api/v1/reminders`
- `PATCH /api/v1/reminders/{reminder_id}`

### Search and export
- `GET /api/v1/search`
- `POST /api/v1/exports`
- `GET /api/v1/exports/{export_id}`

All endpoints require appropriate validation and authorization. These are planned interface contracts, not a claim that the endpoints have already been implemented.

# 7. Security, Privacy and Reliability

Because LifeLog AI stores personal memories, privacy and security must be built into the design.

- Hash passwords using a modern password-hashing algorithm.
- Use secure authentication cookies or a carefully implemented token strategy.
- Enforce user-level authorization on every protected endpoint.
- Validate uploaded file types, sizes and contents.
- Generate safe server-side file identifiers instead of trusting uploaded filenames.
- Store API keys in environment variables or a secrets manager.
- Use HTTPS in production.
- Limit login attempts and expensive AI requests.
- Keep uploaded files private.
- Avoid logging raw diary entries or full transcripts unnecessarily.
- Provide clear consent before sending data to external AI providers.
- Give users control over saved recordings and generated content.
- Support account-data export and deletion.
- Configure database and file-storage backups.
- Make background jobs retryable and prevent duplicate reminder delivery.
- Provide clear error messages without exposing secrets.

# 9. Testing and Acceptance Criteria

The application is not complete merely because the dashboard looks correct.

The following must be tested:

1. A user can register, verify their account and log in.
2. A user can recover access through password reset.
3. A user cannot view or modify another user's private data.
4. A user can record audio in the browser where supported.
5. A user can upload, preview and remove permitted files.
6. Audio transcription can be reviewed and corrected.
7. The system can extract validated structured information.
8. All required generation modes return editable outputs.
9. Memories persist after logout and login.
10. Search and filters return the correct user's data.
11. Tasks can be created, edited, completed and deleted.
12. Confirmed reminders are delivered at the configured time.
13. Failed AI jobs can be retried without corrupting the memory.
14. Exports contain the selected data.
15. Account deletion follows the documented deletion policy.
16. The interface works on desktop and mobile layouts.
17. Missing API keys and service failures are handled clearly.
18. Private files cannot be downloaded by unauthorized users.
