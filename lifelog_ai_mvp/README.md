# LifeLog AI — MVP

LifeLog AI turns a daily note or voice note into a journal entry, reflection, possible pending tasks, a short vlog script, a social caption, and ideas for tomorrow. Each user has a local account and private memory history.

## 1. Requirements

- Python 3.10 or newer
- Internet connection for AI generation/transcription
- A provider API key for live AI generation; the Streamlit MVP retains an explicitly demo-only no-key mode

## 2. Open the project

Extract the ZIP, open the `lifelog_ai_mvp` folder in VS Code, then open its terminal.

## 3. Create a virtual environment

### Windows PowerShell
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

If PowerShell blocks activation, use Command Prompt:
```bat
.venv\Scripts\activate.bat
pip install -r requirements.txt
```

## 4. Configure AI and email providers

1. Copy `.env.example` to `.env`.
2. To use OpenRouter, create an API key and choose a model currently marked free in its model catalog. Set:

   ```dotenv
   LIFELOG_LLM_API_KEY=your_openrouter_key
   LIFELOG_LLM_BASE_URL=https://openrouter.ai/api/v1
   LIFELOG_LLM_MODEL=provider/model:free
   ```

   Replace the model placeholder with an available free model ID. OpenRouter-compatible model availability, quotas, and terms can change. You can instead use an OpenAI API key through the existing `OPENAI_API_KEY` and `OPENAI_MODEL` settings.
3. Configure an email sender as described in **Email delivery** below. In local development, email links are logged to the API console if no provider is configured; that mode is not suitable for real delivery or production.
4. Never commit or share `.env` or provider credentials. AI requests send note text to the provider you configure; do not submit private data unless that external processing is acceptable.

The authenticated API returns a clear service-unavailable error when AI is unconfigured; it does not pretend that a demo response is generated by a real model.

Provider documentation: [OpenRouter API](https://openrouter.ai/docs/api-reference/overview), [OpenRouter model catalog](https://openrouter.ai/models?max_price=0), and [Brevo transactional email](https://developers.brevo.com/docs/send-a-transactional-email).

## 5. Run the app

```bash
streamlit run app.py
```

Streamlit will show a local URL, usually `http://localhost:8501`.

## React frontend

The React + TypeScript frontend lives in `frontend`. Account registration, verification, sign-in, password reset, profile settings, memories, tasks, and mood check-ins use the authenticated FastAPI API and database. The legacy Streamlit app still has its own separate account and data store; the two identity systems have not been merged.

Start the API in a terminal from the `lifelog_ai_mvp` directory:

```powershell
uvicorn backend.main:app --reload
```

In development, account verification/reset links are printed by the API to its console if no email backend is configured. To actually deliver account emails, configure Brevo or SMTP as described below. Console delivery is rejected when `APP_ENV=production`.

For production database setup, set `LIFELOG_AUTH_DATABASE_URL` to a PostgreSQL connection URL, set `LIFELOG_AUTO_CREATE_SCHEMA=false`, and run the Alembic migration:

```powershell
alembic -c .\backend\alembic.ini upgrade head
```

Then start the API and frontend:

```powershell
cd .\frontend
npm install
npm run dev
```

Vite proxies `/api` requests to `http://127.0.0.1:8000` during development. For deployment, serve the frontend and API on the same site or configure a trusted same-site proxy so the HttpOnly session cookie and CSRF protection work together.

## Current MVP features

- Local account registration and sign-in
- Salted password hashing for local authentication
- User-specific SQLite memory history
- Typed daily note
- Browser microphone recording and transcription
- Voice-note upload and transcription
- All eight generation modes, with output-length and custom-prompt controls
- Consistent personal journal format: date, events, wins, challenges, feelings, gratitude, reflection, plans, and closing
- Validated structured day understanding (events, achievements, challenges, plans, and tasks)
- Journal, reflection, tasks, vlog script, caption, tomorrow ideas
- Profile-aware generation and optional, reviewable document text as AI context
- Searchable, titled, tagged SQLite memory history with date filtering
- Memory editing and deletion, including linked tasks and uploaded files
- Manual task creation, completion, and deletion
- Private image and document uploads with PDF/TXT/DOCX text extraction
- Full account export as a ZIP containing JSON data and original uploads
- Password-confirmed account deletion and local file cleanup
- Task due dates, priorities, and in-app reminder indicators
- Scheduled email reminders for tasks with a due date
- Visual memory prompt studio
- Restricted admin health and usage metrics
- FastAPI account API with email verification, password reset, remember-me sessions, server-side expiry, rate limits, CSRF checks, profile preferences, and account-scoped profile-image storage
- Authenticated account-scoped memory, task, and mood APIs with CRUD and cross-user isolation tests
- React dashboard, profile, memories/search, tasks, mood, AI-generation, and Vlog storyboard workflows use authenticated FastAPI endpoints; personal account records are not persisted in browser storage
- Configurable OpenAI-compatible AI provider settings, including OpenRouter endpoints and model IDs
- Transactional account email via SMTP or Brevo API; durable account-task reminder queue and a separately run worker with timezone scheduling, retry backoff, and duplicate prevention

## Known limitations

- Accounts and journal data are stored only in the local SQLite database; this is not production-grade account security.
- Vlog Studio generates and saves text storyboards through the configured AI provider. Video/image generation, attachments, RAG, and several other requested pages are not yet connected.
- Streamlit's legacy local account system and FastAPI account system currently use separate account tables; they are not yet a unified identity service.
- Actual email requires a configured SMTP account or Brevo API key and a verified sender. The account-task reminder worker must remain running to deliver scheduled messages.
- The visual studio creates prompts but does not call an image-generation service.
- Set `LIFELOG_ADMIN_EMAIL` to enable the restricted admin metrics tab for one account.
- Browser push notifications, a visual memory timeline, and production deployment are not implemented.
- The legacy Streamlit no-key demo mode does not perform real AI reasoning; the authenticated React AI studio requires a configured provider.
- The app stores memories in a local SQLite database. Treat personal notes carefully.

## Email reminders

Choose one delivery provider. Check the provider's current free-plan eligibility and sending limits before use.

### Brevo API (transactional account email and FastAPI task reminders)

Create a Brevo account, verify the sender address, and create an API key. Set these values in `.env`:

```dotenv
LIFELOG_EMAIL_BACKEND=brevo
LIFELOG_BREVO_API_KEY=your_brevo_api_key
LIFELOG_SMTP_FROM_EMAIL=your_verified_sender@example.com
LIFELOG_EMAIL_FROM_NAME=LifeLog AI
```

The variable `LIFELOG_SMTP_FROM_EMAIL` is retained as the shared sender-address setting for backward compatibility. Keep the API key private. Registration/verification/reset messages are sent through this provider.

### SMTP alternative

Set `LIFELOG_EMAIL_BACKEND=smtp`, `LIFELOG_SMTP_HOST`, `LIFELOG_SMTP_PORT`, and `LIFELOG_SMTP_FROM_EMAIL`. Add `LIFELOG_SMTP_USERNAME` and `LIFELOG_SMTP_PASSWORD` when required. Use either SSL or STARTTLS, not both. For Gmail, use an app password rather than your regular account password.

### FastAPI account-task reminder worker

Set `LIFELOG_AUTH_DATABASE_URL` to the same database used by the API, enable email notifications in the profile, then create a task with a due date and **Email reminder** enabled. The reminder is scheduled for the profile's preferred time zone and reminder time. Run the worker in a second terminal:

```powershell
python -m backend.reminder_worker
```

For a one-time due-message check:

```powershell
python -m backend.reminder_worker --once
```

The worker stores delivery attempts in the account database, retries temporary failures with backoff, and avoids duplicate deliveries. Do not use console email mode for reminders; the worker refuses to start in that mode.

### Legacy Streamlit reminder worker

The original Streamlit worker uses `LIFELOG_DB_PATH` and its own legacy `users`, `tasks`, and `profiles` tables. To keep it running, configure SMTP and start it separately:

   ```powershell
   python .\reminder_worker.py
   ```

   Keep this process running for scheduled delivery. On a server, run it under a process manager configured to restart it after failures. To check for due reminders once:

   ```powershell
   python .\reminder_worker.py --once
   ```

In either app, set your preferred reminder time in Profile and enable email reminders on tasks with a due date. FastAPI account reminders use `LIFELOG_AUTH_DATABASE_URL`; legacy Streamlit reminders use `LIFELOG_DB_PATH`.

SMTP/API delivery failures are logged and retried with increasing delays. If a worker stops during a send, the delivery is retried after its processing lease expires; as with email delivery generally, this can rarely result in a duplicate message.
